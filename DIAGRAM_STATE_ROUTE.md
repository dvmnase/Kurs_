# Диаграмма состояний: Жизненный цикл маршрута

## Описание процесса

Маршрут проходит через несколько состояний от момента создания перевозчиком до подтверждения владельцем и активации в системе.

## Состояния маршрута

### 1. **Не создан (Not Created)**
- **Описание**: Начальное состояние. Маршрут еще не существует.
- **Условия**: Заявка находится в статусе ACCEPTED, но маршрут еще не предложен.

### 2. **Создается (Being Created)**
- **Описание**: Перевозчик заполняет данные маршрута на фронтенде.
- **Действия**: 
  - Ввод адресов отправления и прибытия
  - Геокодинг адресов
  - Расчет расстояния и времени через Yandex Maps API
- **Файлы**: `front/src/components/RequestChat.tsx` - метод `sendRoute()`

### 3. **Предложен (Proposed)**
- **Описание**: Маршрут отправлен владельцу в виде сообщения типа ROUTE.
- **Условия**: 
  - Заявка в статусе ACCEPTED
  - Перевозчик является участником заявки
- **Действия**:
  - Маршрут сохраняется как JSON в тексте сообщения
  - Сообщение типа ROUTE создается в БД
  - Владелец получает уведомление о новом маршруте
- **Файлы**: 
  - `src/main/java/org/example/bank/services/MessageService.java` - метод `sendRouteMessage()`
  - `src/main/java/org/example/bank/entities/Message.java` - тип ROUTE

### 4. **Ожидает подтверждения (Pending Confirmation)**
- **Описание**: Маршрут предложен владельцу, ожидает его решения.
- **Условия**: 
  - Сообщение с маршрутом существует
  - Владелец еще не подтвердил маршрут
- **Действия**: 
  - Владелец может просмотреть маршрут на карте
  - Владелец может подтвердить или отклонить маршрут

### 5. **Подтвержден (Confirmed)**
- **Описание**: Владелец подтвердил маршрут, он создан в БД и связан с заявкой.
- **Условия**: 
  - Владелец нажал кнопку "Подтвердить маршрут"
  - Пользователь является владельцем заявки
  - Сообщение имеет тип ROUTE
- **Действия**:
  - Создается сущность Route в БД
  - Маршрут связывается с заявкой (confirmedRoute)
  - Устанавливается routeConfirmedAt и routeConfirmedBy
  - Статус заявки меняется на IN_PROGRESS
- **Файлы**: 
  - `src/main/java/org/example/bank/services/MessageService.java` - метод `confirmRoute()`
  - `src/main/java/org/example/bank/entities/Route.java`
  - `src/main/java/org/example/bank/entities/Request.java`

### 6. **Активен (Active)**
- **Описание**: Маршрут подтвержден и заявка находится в процессе выполнения.
- **Условия**: 
  - Заявка в статусе IN_PROGRESS
  - Маршрут связан с заявкой через confirmedRoute
- **Действия**: 
  - Маршрут используется для выполнения доставки
  - Можно отслеживать выполнение заявки

## Переходы между состояниями

### Переход 1: Создание маршрута
- **Из**: Не создан
- **В**: Создается
- **Триггер**: Перевозчик открывает форму создания маршрута
- **Условие**: Заявка в статусе ACCEPTED, перевозчик является участником

### Переход 2: Отправка маршрута
- **Из**: Создается
- **В**: Предложен
- **Триггер**: Перевозчик нажимает "Отправить маршрут"
- **Условие**: Адреса указаны, координаты валидны
- **Действие**: 
  - Расчет расстояния и времени (если не рассчитаны)
  - Создание сообщения типа ROUTE
  - Сохранение маршрута в JSON формате

### Переход 3: Получение владельцем
- **Из**: Предложен
- **В**: Ожидает подтверждения
- **Триггер**: Сообщение сохранено в БД
- **Действие**: Владелец получает уведомление о новом маршруте

### Переход 4: Подтверждение маршрута
- **Из**: Ожидает подтверждения
- **В**: Подтвержден
- **Триггер**: Владелец нажимает "Подтвердить маршрут"
- **Условие**: 
  - Пользователь является владельцем
  - Сообщение типа ROUTE
- **Действие**: 
  - Парсинг JSON данных маршрута
  - Создание сущности Route
  - Связывание с заявкой
  - Изменение статуса заявки на IN_PROGRESS

### Переход 5: Активация маршрута
- **Из**: Подтвержден
- **В**: Активен
- **Триггер**: Статус заявки изменен на IN_PROGRESS
- **Действие**: Маршрут готов к использованию

## Альтернативные переходы

### Отклонение маршрута (неявное)
- **Из**: Ожидает подтверждения
- **В**: Ожидает подтверждения (новый маршрут может быть предложен)
- **Триггер**: Владелец не подтверждает маршрут
- **Действие**: Перевозчик может предложить новый маршрут

### Ошибка создания
- **Из**: Создается
- **В**: Не создан
- **Триггер**: Ошибка при отправке маршрута
- **Условие**: Ошибка валидации или сетевой ошибки

## Диаграмма состояний (PlantUML)

```
@startuml
[*] --> NotCreated : Заявка создана\n(статус ACCEPTED)

NotCreated --> BeingCreated : Перевозчик открывает\nформу создания маршрута

BeingCreated --> BeingCreated : Ввод адресов\nГеокодинг\nРасчет расстояния

BeingCreated --> Proposed : Перевозчик отправляет\nмаршрут (sendRoute)

BeingCreated --> NotCreated : Ошибка отправки\nили отмена

Proposed --> PendingConfirmation : Сообщение сохранено\nв БД

PendingConfirmation --> Confirmed : Владелец подтверждает\nмаршрут (confirmRoute)

PendingConfirmation --> PendingConfirmation : Перевозчик предлагает\nновый маршрут

Confirmed --> Active : Статус заявки\nIN_PROGRESS

Active --> [*] : Заявка завершена

note right of BeingCreated
  Действия:
  - Ввод startAddress, endAddress
  - Геокодинг через Yandex Maps
  - Расчет distance и time
  - Валидация данных
end note

note right of Proposed
  Сохранение:
  - Message с type=ROUTE
  - JSON данные маршрута
  - Связь с Request
end note

note right of Confirmed
  Создание:
  - Route entity в БД
  - Связь request.confirmedRoute
  - request.status = IN_PROGRESS
end note

@enduml
```

## Файлы, участвующие в процессе

1. **front/src/components/RequestChat.tsx**
   - Метод `sendRoute()` - создание и отправка маршрута
   - Метод `confirmRoute()` - подтверждение маршрута (вызов API)

2. **src/main/java/org/example/bank/services/MessageService.java**
   - Метод `sendRouteMessage()` - отправка маршрута в сообщении
   - Метод `confirmRoute()` - подтверждение и создание маршрута

3. **src/main/java/org/example/bank/entities/Route.java**
   - Сущность маршрута в БД

4. **src/main/java/org/example/bank/entities/Request.java**
   - Сущность заявки с полями:
     - `confirmedRoute` - подтвержденный маршрут
     - `routeConfirmedAt` - время подтверждения
     - `routeConfirmedBy` - пользователь, подтвердивший маршрут
     - `status` - статус заявки (RequestStatus)

5. **src/main/java/org/example/bank/entities/Message.java**
   - Сущность сообщения с типом ROUTE

6. **src/main/java/org/example/bank/models/RequestStatus.java**
   - Enum статусов заявки: NEW, PENDING, ACCEPTED, DECLINED, CANCELLED, IN_PROGRESS

## Условия переходов

### Условие для создания маршрута:
- `request.status == ACCEPTED`
- `request.carrier != null`
- `currentUser.id == request.carrier.user.id`

### Условие для подтверждения маршрута:
- `message.type == ROUTE`
- `currentUser.id == request.owner.user.id`
- `message.request.id == request.id`

### Условие для активации:
- `request.confirmedRoute != null`
- `request.status == IN_PROGRESS`

## Действия при переходах

### При переходе "Создается → Предложен":
1. Валидация адресов
2. Расчет расстояния и времени (если не рассчитаны)
3. Сериализация в JSON
4. Создание Message с type=ROUTE
5. Сохранение в БД

### При переходе "Ожидает подтверждения → Подтвержден":
1. Парсинг JSON из message.text
2. Создание Route entity
3. Сохранение Route в БД
4. Установка request.confirmedRoute
5. Установка request.routeConfirmedAt
6. Установка request.routeConfirmedBy
7. Изменение request.status на IN_PROGRESS
8. Сохранение Request

### При переходе "Подтвержден → Активен":
1. Автоматический переход при изменении статуса заявки
2. Маршрут становится доступным для использования
